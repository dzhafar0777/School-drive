# School Drive — UI Kit

## 1. Направление дизайна

- Тёмный интерфейс образовательной платформы.
- Основной фон: глубокий navy / почти чёрный.
- Поверхности: сине-фиолетовые панели с тонкими границами.
- Акценты: фиолетовый и cyan; зелёный — успех, оранжевый — предупреждение, красный — ошибка.
- Скруглённые панели, умеренные градиенты и мягкие свечения. Не использовать glow чрезмерно.
- Типографика: Inter или системный sans-serif с поддержкой кириллицы и тоҷикӣ.

## 2. Цветовые токены

| Token | Value | Использование |
|---|---|---|
| `--sd-bg` | `#06060F` | Основной фон |

## 3. Компоненты

- **Sidebar:** логотип, навигация, активный пункт, профиль и выход.
- **Header:** поиск, уведомления, профиль пользователя.
- **Card:** единый радиус и граница; карточки статистики, курсов, файлов.
- **Button:** primary, secondary, outline, danger; hover, focus, disabled и loading состояния.
- **Form:** label, подсказка, ошибка, focus state; поля не должны полагаться только на placeholder.
- **Badge:** статус материала, задания, аккаунта или модерации.
- **File card:** тип файла, название, размер/дата при наличии, просмотр/скачивание.
- **Empty state:** объяснение отсутствия данных и полезное действие.
- **Modal:** подтверждение, форма или просмотр; поддержка закрытия и клавиатуры.

## 4. Layout и адаптивность

- Desktop: sidebar + рабочая область; сетка карточек.
- Tablet: сокращённая навигация, адаптивная сетка.
- Mobile: sidebar превращается в меню; карточки в одну колонку; таблицы адаптируются или прокручиваются.
- Не допускать горизонтального overflow на узких экранах.

## 5. UX и доступность

- Контраст текста и контролов должен быть достаточным.
- Все интерактивные элементы доступны с клавиатуры.
- Focus state заметен.
- Иконки не заменяют текст в критичных действиях.
- Ошибки формы объясняют, как исправить проблему.
- Destructive actions требуют явного подтверждения.
- Учитывать `prefers-reduced-motion`.

## 6. Правила реализации

1. Сначала проверить существующие CSS, HTML/PHP и компоненты.
2. Переиспользовать текущую архитектуру; не создавать второй UI framework.
3. По возможности внедрять токены через CSS variables.
4. Не менять бизнес-логику при чисто визуальной задаче.
5. Проверить роли, адаптивность, состояния загрузки, ошибки и пустые состояния.
6. Макеты являются ориентиром, не подтверждением уже существующей функциональности.
